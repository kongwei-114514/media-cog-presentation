## 1. 高分辨率下慢在哪？

- 接棒：TTFT = 视觉编码时间 + LLM prefill 时间。
- 原因在 ViT 的结构：从头到尾不降采样，token 数随分辨率平方增长，每层都要对所有 token 做自注意力。
- Fig. 5 只说明一件事（注意：它画的是 FastVLM 自己的模型，不是 ViT）：哪怕 token 已经压得很少，分辨率一高，**视觉编码本身**仍是大头。所以光减少 token 不够，编码器也得快。
- 切图、剪枝这些做法一句话带过：都是在 ViT 外面打补丁。
- 抛出问题：能不能换一个**天生适合高分辨率**的编码器？

## 2. 前人的编码器长什么样？

- 先说清楚一件事：**这篇论文只换了流水线里的第一个框，也就是视觉编码器**；投影层和 LLM 沿用 LLaVA。下面讲的 stage，都是这个编码器的内部结构。
  - 做法：第一次放 stage 图时，把它画在流水线的“视觉编码器”框里，让大家一眼看出它在系统里的位置。
- 放 **FastViT 的 stage 图**（[放大 A 原图](figures/zoomA_fastvit_stage_column.png)），只讲整体：
  - 金字塔：stem 加 4 个 stage，每过一个 stage，图就缩小一次；
  - 混合：前 3 个 stage 用卷积（便宜，看局部），最后 1 个用自注意力（贵，看全局）；
  - 和“切块”对上：ViT 一开始就切成 14×14 像素的块，之后 token 数不变；金字塔是一边算一边缩小，**最后剩下几个位置，就是几个 token**。
- 一句话：这个思路本身就比 ViT 适合大图。FastVLM 的第一步就是直接拿它来用，方向是对的。
- 过渡：但要推到更高分辨率、再把模型放大时，问题就出来了。

## 3. 哪里不适合高分辨率？（重点）

原图字太小，把要讲的部分**裁出来放大**（图在 `draft/figures/`）：

| 放大哪块 | 讲什么 |
|---|---|
| **A. 左侧 stage 列**：[标注版](figures/zoomA_fastvit_stage_column_annotated.png)（已标 4× → 32×） | 已经能压 32 倍了，可 1024² 的图最后还剩 32×32 = 1024 个 token 交给 LLM，还是太多。**能不能再压？** |
| **B. Stage 4 的 Attention 块**：[图](figures/zoomB_fastvit_stage4_attention.png) | 见下面的逻辑链 |
| **C. RepMixer（可选）**：[图](figures/zoomC_fastvit_repmixer.png) | 这是**适合**大图的设计：训练时多条支路，推理时合成一个卷积。后面原样保留，一句话带过 |

**B 的逻辑链：**

1. 编码器越大，看图能力越强，所以作者想把它放大。
2. 之前的混合模型放大时，习惯在 stage 3、4 多堆自注意力层，因为自注意力是能力最强的层。
3. 这些设计原本面向 224² 的小图：stage 3 压了 16 倍，只剩 14×14 = 196 个位置，自注意力很便宜。
4. 换成 1024²：stage 3 还有 64×64 = 4096 个位置，多了约 20 倍。自注意力开销跟位置数的平方成正比，贵了约 400 倍。

- **小结**：A 和 B 是同一个病根，**压得不够**。B 是做自注意力之前压得不够，计算爆炸；A 是交给 LLM 之前压得不够，token 太多。

## 4. 怎么改？为什么这样改能行？（重点）

### 4.1 想法：再压一层

- 加第 5 个 stage，再缩小一次：总共压 64 倍，自注意力只放在已经压到 32 倍、64 倍的地方。**一个改动同时治好 A 和 B。**
- 把 FastViT 的 stage 列（放大 A）和 FastViTHD 的 stage 列（[标注版](figures/fastvithd_stage_column_annotated.png)）**并排放**：多了一个 stage，自注意力往后挪了。
- 一组 token 数（都按 1024² 输入）：ViT 约 5300 个 → FastViT 1024 个 → FastViTHD 256 个。

### 4.2 为什么别人没早这么做？

- 代价：压得越狠，每个 token 盖住的区域越大，小字这类细节就越容易丢。
- 当时的主流看法甚至是往少里压：ViTamin 建议总共只压 16 倍。
- 所以真正的问题是：**怎么压，才能不丢东西？**

### 4.3 怎么压到点上

1. **先看细节，再压缩**：图还大的时候，用便宜的卷积把细节处理掉；压小以后，才交给自注意力做全局理解。
2. **空间换通道**：每压一次，长宽减半、通道翻倍，最后到 1536 维。信息尽量挪进通道里，而不是直接扔掉。
3. **多尺度特征**：从前面几个 stage 把细节再拉回来（stage 条下方的几条支路）。

### 4.4 为什么性能反而更高

- 同样的 token 数，能看更高分辨率的图：同样 256 个 token，ViT 只能看 224² 的图，FastViTHD 能看 1024²。
- 对 VLM 来说，分辨率才是关键。所以**压缩不是牺牲，压缩换来的是分辨率**。

## 5. 还要付出什么代价？

1. **压得狠，对训练的要求就高**：每个 token 要装更多信息，FastViTHD 背后是一套很强的图文预训练（大数据，加大模型当老师）。
2. **分辨率要和 LLM 大小匹配**：给很小的 LLM 喂超高分辨率的图，它也用不上。视觉端压得再好，整个系统还是要两头一起调。

- 收尾一句：从编码器内部重新设计，而不是在外面打补丁。
