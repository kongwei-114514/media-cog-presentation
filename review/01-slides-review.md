## 1. 核心图文不匹配问题：P8「自注意力放得太早」

### 现象描述
第 8 页（`# 自注意力放得太早`）左侧配图 [`zoomB_fastvit_stage4_attention.png`](../draft/figures/zoomB_fastvit_stage4_attention.png) 与右侧文字及表格所讲内容不在同一维度，图文之间缺乏对应关系。

### 原因拆解
1. **右侧文字讲的是「宏观阶段位置与特征图尺寸（Stage-level）」**：
   - 文字指出：将 4 阶段混合模型放大时（对应 `FastViT-Naive Scaling`），习惯在 **Stage 3（压 16 倍）** 和 Stage 4 多堆自注意力层；
   - 表格对比了 **Stage 3（压 16 倍）** 下 $224^2$ 小图（$14\times 14 = 196$ 个位置）与 $1024^2$ 大图（$64\times 64 = 4096$ 个位置）的位置数差异，说明自注意力开销随位置数平方增长（贵约 400 倍）。
2. **左侧配图画的却是「单个自注意力块内部的算子重参数化（Operator-level）」**：
   - [`zoomB_fastvit_stage4_attention.png`](../draft/figures/zoomB_fastvit_stage4_attention.png) 裁剪自第 5 页 `FastViT` 原图（[`fastvit_arch.png`](../paper/figures/fastvit_arch.png)）中间 `(a)` 的底部米色框；
   - 原图中该框左右两列分别对应 **训练态（Training）** 与 **推理态（Inference）**，中间箭头表示条件位置编码（`CPE`）将旁路 `7x7 DW Conv` 合并进单层的结构重参数化过程；
   - 裁剪后不仅丢失了顶部的 `Training / Inference` 表头（导致左右两列与中间箭头含义不明），而且图中的 `CPE`、`BatchNorm`、`ConvFFN` 等微观结构与右侧文字讨论的「Stage 3 下采样 16 倍、位置数从 196 暴增至 4096」毫无关联。
3. **与前一页（P7）存在视觉断层**：
   - 在 P7（[`zoomA_fastvit_stage_column_annotated.png`](../draft/figures/zoomA_fastvit_stage_column_annotated.png)）中，展示的原版 `FastViT` 的 **Stage 3 是灰色框（卷积）**，只有 Stage 4 是米色框（自注意力）；
   - 到了 P8，文字直接开始计算「Stage 3（压 16 倍）做自注意力」的开销，但画面上并未展示「模型放大时把 Stage 3 也改成了自注意力」。

## 2. 跨页脉络割裂问题：P12～P15（「怎么压到点上」主线连续性）

### 现象描述
第 12 页（`# 怎么压到点上`）放出了标注有 `① 先看细节，再压缩`、`② 通道数`、`③ 多尺度特征` 的 `FastViTHD` 横版核心架构图（[`fastvithd_stages_p9_annotated.png`](../draft/figures/fastvithd_stages_p9_annotated.png)），并将 ② 和 ③ 拆到了后续页面展开。但在翻到后面的页面（P13、P14、P15）时，P12 这张总览架构图完全消失，导致听众容易忘记当前正在回答什么总问题、也看不出当前讲的局部机制对应架构图里的哪个位置，整条思路被拆散割裂。

### 具体断层表现
1. **局部解释脱离了 P12 的架构总图锚点**：
   - P12 在架构图上标出了 ①、②、③ 三个位置，并预告 `② 空间换通道（下一页）`、`③ 多尺度特征（再下一页）`；
   - 然而翻到 P13（`# ② 空间换通道`）和 P14（`# ③ 多尺度特征：图里的 C 是什么？`）时，画面全部换成了抽象的三维长方体示意图（[`p13_channel_stack.png`](../draft/figures/p13_channel_stack.png)、[`p14_multiscale_concat.png`](../draft/figures/p14_multiscale_concat.png)），P12 的横版架构图不再出现；
   - 尤其是 **P14 标题直接问「图里的 C 是什么？」**，但带有 `C` 节点的原架构图远在 P12，听众在 P14 画面上根本看不到原架构图里的分支和 `C` 在哪。
2. **连续展开概念后容易忘掉主线问题（P12 $\rightarrow$ P14/P15）**：
   - P11～P15 本质上是一条完整的逻辑线：回答 **「压 64 倍为什么不会把细节丢光，反而看得更清？」**；
   - 因为中间连续插入了「什么是通道」「什么是 Learned Pool 和拼接 C」的拆解页，到了 P14、P15 时，如果页面上没有 P12 的架构图或主线锚点做串联，听众很容易陷入局部概念解释，忘了这几页合在一起是在回答「`FastViTHD` 怎么压 64 倍还不丢细节」这个核心问题。
3. **后续改进方向记录**：
   - 在拆解页（如 P13、P14）及收束页（P15）保留或同步展示 P12 的 `FastViTHD` 横版架构图（或将其作为同页锚点/局部高亮对照），让「总架构位置 $\leftrightarrow$ 局部机制原理 $\leftrightarrow$ 最终分辨率收益」始终处于同一条视觉主线上。

## 3. 逻辑未讲透与归因错位：P17「代价②：分辨率要和 LLM 大小匹配」

### 现象描述
第 17 页（`# 代价②：分辨率要和 LLM 大小匹配`）目前仅写了「给很小的 LLM 喂超高分辨率的图，它也用不上」「视觉端压得再好，整个系统还是要两头一起调」，并在页面最下方放了一句红字「**从编码器内部重新设计，而不是在外面打补丁**」。

### 问题分析
1. **核心意思只说了一半，缺少关键转折**：
   - 提升视觉编码器（高分辨率输入 + 高密度压缩 Token）确实是以**对后端 LLM 提出更高能力要求**为代价的（小尺寸 LLM 无法充分消化高分辨率视觉信息，必须搭配更大规模的 LLM 才能发挥威力）；
   - 但这一页真正要传达的核心重点（对应论文 Sec. 3.2.1 与 Fig. 4 [`decoder_encoder_ablation.png`](../paper/figures/decoder_encoder_ablation.png)）是：**即便需要 LLM 规模配合，升级视觉编码器相比于「只提升 LLM 而不改编码器」依然具有压倒性的系统优势（整体帕累托前沿显著上移、同精度下快 3 倍）**。现有文案停留在「小 LLM 用不上、还得两头一起调」，没有把「改进编码器比单纯堆大 LLM 划算得多」这一核心优势落下来。
2. **底部红字归因错位**：
   - 页面最下方的红字「从编码器内部重新设计，而不是在外面打补丁」针对的是第 3 页提到的外部切图/剪枝方案，与本页上方讨论的「Encoder 与 LLM 的协同关系」并非因果关系；直接放在本页底部容易让人误以为是从上面两条推导出的结论。

### 更改思路（按论文 Sec. 3.2.1 主线理顺）
- 先讲清**代价**：编码器推向高分辨率与高压缩后，信息密度更高，需要更大容量的 LLM 配合才能吃下这部分增益（小 LLM 会提前饱和）；
- 再落脚到**核心优势**：对比「升级编码器 + 匹配 LLM」与「不改编码器、只靠放大 LLM」，明确指出改编码器能够把整个 VLM 系统的精度-延迟上限全面抬高；
- 将底部结论回归到「编码器对整个 VLM 系统上限的决定作用」上，避免与外部“打补丁”口号混杂。
